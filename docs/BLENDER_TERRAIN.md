# Рельеф мест из «Марсианина» в Blender — ТЗ

Модели рельефа двух мест из «Марсианина»: Ares 3 (место посадки и база Уотни) и Ares 4 (ракета MAV в кратере Скиапарелли). Они строятся из реальных моделей рельефа HiRISE, файлы собирает скрипт [`backend/scripts/build_martian_obj.py`](../backend/scripts/build_martian_obj.py). Задача — подготовить из них сцены для демо и лёгкие модели для локальной 3D-сцены на сайте.

## 1. Что есть на входе

| Файл | Место | Сетка | Участок | Перепад высот |
|---|---|---|---|---|
| `ares3_acidalia_hirise.obj` | Ares 3, Acidalia Planitia: точка, координаты которой Энди Вейр передал команде HiRISE | 532 × 1488 вершин, шаг 8 м | 4,4 × 12,3 км | 69 м (−4157…−4088 м) |
| `ares4_schiaparelli_hirise.obj` | Ares 4, дно кратера Скиапарелли | 284 × 2168 вершин, шаг 8 м | 2,3 × 17,6 км | 130 м (−512…−382 м) |

У каждой модели рядом лежат:

- `*.mtl` — материалы `ortho` (снимок HiRISE) и `hypso` (раскраска по высоте);
- `*_ortho.png` — ортофото HiRISE в границах модели;
- `*_hypso.png` — гипсометрическая раскраска;
- `*_preview.png` — карта высот для сверки ориентации;
- `*.json` — источник, ID продукта, кредит, границы, высоты, вертикальное преувеличение.

Модели узкие и длинные, потому что так снимает HiRISE: полоса съёмки около 5 км шириной. Края полосы пустые (NoData), и скрипт вырезает только участок с данными.

## 2. Как получить файлы

Готовые OBJ весят 60–80 МБ, поэтому в Git их нет. Собрать из папки `backend`:

```bash
pip install -e ".[terrain]"
python scripts/build_martian_obj.py --site all --out ../data/obj
```

Параметры:

- `--site ares3 | ares4 | all` — какое место собрать;
- `--step-m 8` — шаг сетки в метрах. Чем меньше шаг, тем больше деталей и тяжелее файл. Минимум 1 м для Ares 3 и 2 м для Ares 4: это разрешение исходных данных, мельче не бывает.
- `--vexag 2.5` — вертикальное преувеличение. Рельеф здесь пологий, и без преувеличения выглядит плоским. Для честного масштаба поставьте `--vexag 1`.

Папка `data/obj/` в `.gitignore`.

## 3. Система координат модели

- 1 единица = 1 км.
- X — на восток, Y — на север, Z — вверх.
- Z = (высота − минимум участка) × vexag. Абсолютная высота минимума записана в JSON (`z_min_m`, в метрах относительно ареоида Марса).
- Начало координат — юго-западный угол участка.

## 4. Импорт в Blender (4.x)

1. File → Import → Wavefront (.obj).
2. В настройках импорта: **Up Axis = Z**, **Forward Axis = Y**. По умолчанию Blender ждёт Y-up и положит модель на бок.
3. Scale оставить 1.
4. После импорта: правая кнопка → Shade Smooth (или Shade Auto Smooth).
5. Для удобства: Scene Properties → Units → Length = Kilometers, Unit Scale = 1000. Тогда размеры в интерфейсе будут в километрах, как в модели.

Сверка после импорта: вид сверху (Numpad 7) должен совпадать с `*_preview.png` — север вверху, кратеры на тех же местах.

## 5. Материалы

- По умолчанию назначен `ortho`: Principled BSDF с текстурой снимка.
- Чтобы переключиться на гипсометрию: Shading → узел Image Texture → открыть `*_hypso.png`.
- Ортофото чёрно-белое: HiRISE RED — это яркость, а не цвет. Тонировать под марсианский цвет можно, например через ColorRamp, но на слайдах подписывать «тонировано», а не «естественный цвет».
- Roughness около 0,9, Specular около 0: грунт матовый.

## 6. Свет и камера

- Sun: угол 25–40° над горизонтом. Низкое солнце лучше показывает пологий рельеф.
- Цвет неба/World: пыльный желто-коричневый, интенсивность невысокая.
- Clip End камеры не меньше 30 (км).
- Для облёта: камера по кривой (Follow Path) на высоте 0,05–0,3 км над поверхностью.

## 7. Что нужно на выходе

| Результат | Требования |
|---|---|
| Рендеры для презентации | По 2–3 кадра на место, 1920×1080, PNG. В подписи кадра: место, источник, преувеличение (например «рельеф ×2,5») |
| Облёт | 10–20 с, 1080p, MP4. Те же подписи в титрах |
| Модели для сайта | `ares3.glb` и `ares4.glb`: до 200 тыс. треугольников (модификатор Decimate или Remesh), сжатие Draco, текстура не больше 4096 px. Размер файла не больше 15 МБ |

При экспорте в glTF: Blender сам переведёт оси в Y-up, это нормально для Three.js. Масштаб по X и Y не менять: 1 единица = 1 км. Преувеличение по Z — то, что записано в JSON. Если меняли, записать новое значение.

## 8. Правила честности данных

- Не досочинять рельеф: не лепить скульптингом скалы и камни, не добавлять кратеры. HiRISE DTM различает детали от нескольких метров, и это реальная поверхность.
- Если для красоты нужны камни или поверхность у ног (декор), класть их отдельным объектом в коллекцию `decor` и в демо подписывать как художественное дополнение.
- Пустые участки не заполнять выдуманным рельефом.
