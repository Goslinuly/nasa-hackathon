# Участки прогулки в Blender — ТЗ

Цель: для каждого участка режима «От первого лица» получить в Blender сцену с настоящим рельефом HiRISE, рендеры с высоты глаз (1,7 м) и лёгкую модель `.glb` в той же системе координат, что и прогулка на сайте.

> **Ставить через pip ничего не нужно.** Скрипт запускается внутри Blender его собственным Python (там уже есть numpy). Данные тоже готовы: пакеты участков лежат в репозитории в `frontend/public/data/local/<участок>/`. GDAL, rasterio и `pip install -e ".[terrain]"` для этой задачи не нужны. Старая инструкция с ними описывала другой путь (раздел 9) и именно на нём всё ломалось.

## 1. Что нужно

- Blender **4.2 или новее** (проверено на 5.3). Скачать с blender.org или `brew install --cask blender`.
- Клон репозитория `nasa-hackathon`, ветка `main`, после `git pull`.
- Для Солнца — JSON вида `gale_day.json` (раздел 4) или просто высота и азимут.

## 2. Участки

| `--site` | Место | Размер | Сетка высот | Снимок |
|---|---|---|---|---|
| `gale-boxwork` | Гейл, район boxwork на склоне горы Шарп (путь Curiosity) | 1,8 × 2,4 км | 2 м | 0,5 м |
| `ares3` | Ares 3, Acidalia Planitia («Марсианин») | 2 × 2 км | 2 м | 0,5 м |
| `jezero` | Езеро, западный вал кратера (путь Perseverance) | 3 × 2 км | 2 м | 0,5 м |

Точки съёмки — метки `pois` из `manifest.json` каждого участка. Это те же точки, что на сайте в «Перейти к точке».

## 3. Запуск: одна команда на участок

JSON с Солнцем и HDR неба (из `sites.zip`) положить в папку `sites/` в корне репозитория. Она в `.gitignore`, потому что HDR весит 32 МБ. Дальше, из корня репозитория:

```bash
blender --background --python backend/scripts/blender/site_scene.py -- \
    --site gale-boxwork --sun sites/gale_day.json
```

`--` обязателен: всё, что после него, получает скрипт, а не Blender.

На macOS, если команды `blender` нет: `/Applications/Blender.app/Contents/MacOS/Blender`. На Windows: `"C:\Program Files\Blender Foundation\Blender 4.2\blender.exe"`.

Результат появится в `data/blender/<участок>/` (папка в `.gitignore`):

| Файл | Что это |
|---|---|
| `<участок>_<точка>_<курс>.png` | Рендеры с высоты глаз 1,7 м. Подпись (место, продукт, кредит, «рельеф ×1», «снимок тонирован», время) впечатана в кадр |
| `<участок>.glb` | Модель для сайта: Draco, текстура JPEG 2048 px, около 1 МБ |
| `<участок>.blend` | Вся сцена. Её можно открыть и докрутить свет, камеры, декор |
| `<участок>_scene.json` | Паспорт: система координат, base_m, Солнце, список рендеров, кредиты |

Полный прогон Гейла на Mac с GPU (4 кадра 1920×1080 по 64 сэмпла) занимает несколько минут. Для черновика: `--res 960x540 --samples 16`.

### Параметры

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--site` | — | `gale-boxwork`, `ares3`, `jezero` |
| `--sun file.json` | — | Солнце из JSON (раздел 4) |
| `--sun-el 30 --sun-az 250` | — | Вместо JSON: высота и азимут Солнца (от севера по часовой), в градусах |
| `--sky-hdr file.hdr` | нет | HDR неба (equirect), например `gale_night_sky.hdr` для ночи |
| `--headings 0,90` | `auto` | Курсы камеры. `auto` — поперёк Солнца: боковой свет лучше всего показывает рельеф |
| `--engine cycles\|eevee` | `cycles` | EEVEE быстрее, Cycles честнее по свету |
| `--samples` / `--res` | `64` / `1920x1080` | Качество и размер кадра |
| `--step` | `1` | Шаг сетки рендера в пикселях высот (1 = все 2 м) |
| `--glb-step` / `--glb-texture` | `4` / `2048` | Шаг сетки GLB (4 × 2 м = 8 м) и размер текстуры |
| `--no-render` / `--no-glb` | — | Пропустить рендер или GLB |
| `--vexag` | `1` | Вертикальное преувеличение. **Для прогулки только 1** |

### Готовые команды

```bash
# Гейл днём и ночью
blender -b --python backend/scripts/blender/site_scene.py -- --site gale-boxwork --sun sites/gale_day.json
blender -b --python backend/scripts/blender/site_scene.py -- --site gale-boxwork --sun sites/gale_night.json \
    --sky-hdr sites/gale_night_sky.hdr --headings 0,180 --no-glb --out data/blender/gale-boxwork-night

# Езеро днём
blender -b --python backend/scripts/blender/site_scene.py -- --site jezero --sun sites/jezero_day.json

# Ares 3: низкое Солнце, чтобы читалась пологая равнина
blender -b --python backend/scripts/blender/site_scene.py -- --site ares3 --sun-el 20 --sun-az 250
```

## 4. Солнце: формат JSON

Скрипт берёт из JSON поля:

```json
{
  "sun_dir_enu": [0.4937, 0.2380, 0.8364],
  "sun_elevation_deg": 56.77,
  "sun_azimuth_deg": 64.27,
  "sun_strength_wm2": 289.4,
  "sun_angular_diameter_deg": 0.331,
  "is_night": false,
  "name": "gale_day", "ltst_hours": 10.0, "utc": "2026-11-14T12:18:28", "tau": 0.5
}
```

- `sun_dir_enu` — единичный вектор на Солнце: восток, север, вверх.
- Сила лампы Sun = `sun_strength_wm2 × 0,012`. Это художественная калибровка под AgX, а не фотометрия: 290 Вт/м² дают около 3,5.
- Если `is_night: true`, Солнце не ставится. Без `--sky-hdr` будет почти чёрный кадр, и это честно: Луны, которая подсветила бы грунт, у Марса нет.
- Координаты Солнца считать **для центра участка** из `manifest.json` (`center.lat`, `center.lon_east`). Например, в нынешнем `gale_day.json` стоят −5,4° / 137,8°, а центр boxwork — −4,804° / 137,383°. Разница в положении Солнца маленькая, но лучше пересчитать.

## 5. Система координат

Совпадает со сценой прогулки (`frontend/src/features/walk/walkScene.ts`), поэтому GLB можно класть в сцену без сдвигов:

- 1 единица = 1 м.
- В Blender: X — восток, Y — север, Z = высота − `base_m` из манифеста. Начало координат — центр участка.
- В GLB (экспорт с Y вверх): X — восток, Y — вверх, Z — юг, как в `walkScene.ts`.
- Абсолютная высота точки = Z + `base_m` (метры относительно ареоида, как в HiRISE DTM USGS).

## 6. Что можно и что нельзя

Можно:
- Докручивать в `.blend` свет, экспозицию, цвет неба, камеры, облёт.
- Добавлять камни и пыль у ног **отдельной коллекцией `decor`**. На кадрах с декором подписывать «художественное дополнение».

Нельзя:
- Досочинять рельеф: шум, displacement, скульптинг, процедурные кратеры. Сетка — это реальный DTM с шагом 2 м, мельче данных нет.
- Заполнять NoData. Дыры в сетке остаются дырами, так задумано.
- Менять масштаб или преувеличение для прогулки.
- Называть цвет естественным. HiRISE RED — это яркость, цвет тонирован (`MARS_TINT` в скрипте).

## 7. Разбор `galecode.glb` (что было не так)

Присланный файл — это не участок прогулки, а весь кратер Гейла с горой Шарп:

| | `galecode.glb` | Нужно для прогулки |
|---|---|---|
| Рельеф | обзорный, около 200 м/пиксель (уровень MOLA/HRSC), 250 × 250 единиц | HiRISE DTM 2 м, участок 2 км |
| Масштаб | единица не равна метру, у узла scale 0,66, высоты 0–15 единиц | 1 ед. = 1 м, рельеф ×1 |
| Материал | процедурный (`Mars_Procedural_Code`). В glTF процедурные узлы не попадают, на сайте модель будет серой | текстура снимка HiRISE внутри GLB |
| Солнце | узел `Sun` без света: glTF без `KHR_lights_punctual` | свет задаёт сцена сайта, в GLB он не нужен |
| Размер | 87 МБ, 3,1 млн треугольников, без сжатия | ≤ 15 МБ, Draco (скрипт даёт около 1 МБ) |
| Привязка | нет | центр участка, оси как в `walkScene.ts` |

Для облёта всего кратера такая модель годится, но в подписи нужно указать «обзорный рельеф ~200 м/пикс» и источник DEM. С высоты глаз на ней ничего не видно: один пиксель — 200 м.

Из `sites.zip` пригодились `gale_day.json`, `gale_night.json`, `jezero_day.json` и `gale_night_sky.hdr`. Скрипт читает их как есть.

## 7а. Кратер как дальний план: HiRISE под ногами, `galecode.glb` на горизонте

Вблизи `galecode.glb` чётче не станет: в нём нет деталей мельче 200 м. Правильная схема — вложенные уровни. Под ногами — HiRISE 2 м из пакета участка, за краем участка — её кратер: стены, гора Шарп, горизонт. Скрипт делает это сам:

```bash
blender -b --python backend/scripts/blender/site_scene.py -- \
    --site gale-boxwork --sun sites/gale_day.json --backdrop sites/galecode.glb
```

`galecode.glb` положить в `sites/` (папка в `.gitignore`).

Что скрипт делает с подложкой:
1. Берёт сетку меша. Трансформ узла (scale 0,66) не используется.
2. Привязывает по калибровке `backend/scripts/blender/backdrops/galecode.json`. Её подобрали по MOLA MEGDR, корреляция 0,993: центр −5,4° / 137,8°, 1 ед. = 1 км, без поворота. Высота = 386,81 м × единицу − 4585,4 м, то есть в файле рельеф был завышен в 2,585 раза. Скрипт возвращает ×1.
3. Переводит в систему координат участка (метры, центр участка).
4. Вырезает подложку под HiRISE-участком. У края опускает её на 3 м ниже HiRISE и плавно, на 4 км (`--backdrop-feather-km`), сводит к её собственным высотам. У boxwork подложка была выше HiRISE примерно на 66 м — это убирается этим переходом.
5. Ставит дальнюю плоскость камеры на 300 км и дописывает в подпись кадра «дальний план: обзорный рельеф ~200 м/пикс, без снимка».
6. Кладёт отдельный `gale-boxwork_backdrop.glb` (сетка 1 км, около 0,1 МБ) рядом с моделью участка.

### Езеро: `jezerocode.glb`

То же самое для Езеро:

```bash
blender -b --python backend/scripts/blender/site_scene.py -- \
    --site jezero --sun sites/jezero_day.json --backdrop sites/jezerocode.glb
```

Калибровка — `backend/scripts/blender/backdrops/jezerocode.json`. Сетка 500 × 500, шаг по востоку уже сжат на cos 18,4°, 1 ед. = 1 км. Положение уточнено по высотам участка прогулки (корреляция 0,988): центр 18,444° / 77,46°, а не 18,4° / 77,5°, как в JSON Солнца. Вертикаль — по MOLA: 354,2 м на единицу, рельеф в файле завышен в ~2,8 раза.

`jezero_night.json` внутренне противоречив: вектор `sun_dir_enu` даёт азимут ~124°, а не 326°, и при LTST 02:00 на 18° с. ш. Солнце стоит около −60…−70°, а не −12°. На рендер это не влияет (при `is_night: true` Солнце не ставится), но значения стоит пересчитать тем же способом, что и дневные.

### Подложка на сайте

`<участок>_backdrop.glb`, собранный с `--backdrop-glb-step 2` (сетка 400 м), лежит в пакете как `frontend/public/data/local/<участок>/backdrop.glb` и прописан в `manifest.json` (блок `backdrop`). Прогулка рисует его отдельным дальним проходом до 300 км с пылевой дымкой. Сейчас подложки есть у `gale-boxwork` и `jezero`.

Если модель кратера пересобрать (другой размер, центр, масштаб высот), калибровка перестанет подходить. Тогда скрипт остановится с ошибкой, если сетка не квадратная. Если сетка та же, но высоты другие, картинка будет неправильной без всякой ошибки. Поэтому `galecode.glb` не менять. Если нужна новая версия — прислать её, калибровку пересчитаем (`sha256` исходного файла записан в JSON).

## 8. Приёмка

- [ ] Для каждого участка есть 2–4 рендера 1920×1080 с впечатанной подписью.
- [ ] Вид сверху (Numpad 7) в `.blend` совпадает с мини-картой на сайте: север вверху.
- [ ] `<участок>.glb` ≤ 15 МБ, открывается в https://gltf-viewer.donmccurdy.com/ с текстурой (не серый).
- [ ] В `<участок>_scene.json` стоит `"vexag": 1`.
- [ ] Декор, если есть, лежит в коллекции `decor` и подписан.

## 9. Приложение: большие OBJ Ares 3 / Ares 4 (не для прогулки)

Для облётов на 12–17 км есть [`backend/scripts/build_martian_obj.py`](../backend/scripts/build_martian_obj.py). Он режет исходные GeoTIFF HiRISE и требует обычный Python 3.11+ с GDAL/rasterio (`pip install -e ".[terrain]"` из `backend`, лучше в venv). Ставить это **в обычный Python, а не в Blender**. Ошибка «pip install не работает» обычно значит, что ставили в Python Blender или без venv. Для задач из разделов 1–8 этот путь не нужен.
