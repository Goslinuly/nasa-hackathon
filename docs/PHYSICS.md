# Физика и математика Martian Map

Разбор всех расчётных моделей проекта: что за физика, откуда формула, какие константы, где границы применимости и в каком файле это живёт.

Порядок разбора каждой величины один и тот же: **физический смысл → формула → обозначения и единицы → константы → область применимости → файл**.

Важно для чтения всего документа: Гейл, Езеро и Ares 3 — это участки, на которых проверяется детальный масштаб (сетка 1–2 м). Продукт работает по всей планете, и для произвольной точки те же формулы считаются на тех данных, которые для неё есть: глобальный рельеф MOLA/HRSC вместо HiRISE. Выбор участка меняет разрешение входных данных, а не модель.

Обозначение статуса каждой величины, то же, что в интерфейсе:

| Статус | Что значит |
|---|---|
| **данные** | измерение миссии, приходит из файла или API |
| **модель** | формула с опубликованным выводом |
| **правило** | эксплуатационное соглашение, не физика |
| **оценка** | коридор, когда источники расходятся |

## 0. Системы координат и единицы

Три системы, между которыми всё переводится.

**ICRF** — небесная инерциальная система, оси фиксированы относительно далёких квазаров. В ней заданы координаты звёзд (α, δ) и панорама Млечного Пути.

**Связанная с телом (body-fixed)** — вращается вместе с Марсом, ось *z* по оси вращения, нулевой меридиан по кратеру Airy-0.

**ENU** — локальная система наблюдателя: *x* на восток, *y* на север, *z* в зенит. В ней считаются высота и азимут.

Оси сцены прогулки отличаются от ENU (у three.js *y* вверх): сцена — *x* восток, *y* вверх, *z* юг. Перевод:

```
ENU → сцена:  (e, n, u) → (e, u, −n)
сцена → ENU:  (x, y, z) → (x, −z, y)
```

Файл: `frontend/src/features/sky/skyMath.ts`, функции `sceneToEnu` / `enuToScene`.

Единицы везде СИ, кроме специально оговорённых: уклон в градусах, уклон в метаболической формуле — в процентах, кислород в литрах и л/мин, доза в мЗв, время в секундах либо в марсианских часах.

Радиус Марса используется двух видов, и это не ошибка:

| Величина | Значение | Где |
|---|---|---|
| Экваториальный радиус | 3396,19 км | глобус, тайлы (`features/globe/tiles.ts`) |
| Средний радиус | 3389,5 км | метры на градус в 2D-карте (`features/map/mapTiles.ts`) |

Марс заметно сплюснут, поэтому для сферы глобуса берётся экваториальный радиус, а для перевода «градус → метр» на плоской карте — средний.

## 1. Время на Марсе и положение Солнца

Основа — алгоритм **Mars24** NASA GISS (Allison & McEwen, 2000). Реализован дважды независимо: `frontend/src/shared/time/mars24.ts` (глобус, HUD) и `frontend/src/features/sky/marsTime.ts` (прогулка). Тест `shared/time/crosscheck.test.ts` держит их вместе: MSD до 10⁻⁶ сола, высота Солнца до 0,5°.

### 1.1 Шкала времени

Переход от земного UTC к динамическому времени TT:

```
JD_TT = 2440587,5 + t_unix / 86 400 000 + (TT − UTC) / 86 400
```

где `TT − UTC = 69,184 с` = 32,184 с (TT − TAI) + 37 с накопленных високосных секунд на 2026 год. Это не настройка, а две разные причины расхождения шкал: первая — определение TT через атомное время, вторая — замедление вращения Земли.

```
Δt_J2000 = JD_TT − 2 451 545,0        (дни от эпохи J2000)
```

### 1.2 Марсианская сольная дата

**MSD** — счётчик марсианских солнечных суток, аналог юлианской даты. От него считается всё остальное:

```
MSD = (Δt_J2000 − 4,5) / 1,027 491 252 + 44 796,0 − 0,000 96
```

Делитель **1,027 491 252** — отношение длительности марсианских солнечных суток к земным. Отсюда длина сола:

```
T_сол = 86 400 × 1,027 491 252 = 88 775,244 с = 24 ч 39 мин 35,244 с
```

Константа `SOL_SECONDS = 88775.244`. Обратный переход `unixMsFromMarsSolDate` — та же формула, решённая относительно времени; он нужен, чтобы по заданному местному времени найти момент UTC.

### 1.3 Орбита: средняя аномалия и уравнение центра

Марс движется по эллипсу, поэтому угловая скорость непостоянна. Средняя аномалия — равномерно растущий угол:

```
M = 19,3871° + 0,524 020 73° · Δt_J2000
```

Коэффициент 0,52402°/сут даёт период 360/0,52402 ≈ 687 суток — марсианский год.

Разность истинной и средней аномалии (уравнение центра) раскладывается в ряд по синусам кратных углов плюс возмущения от других планет:

```
ν − M = (10,691° + 3·10⁻⁷ · Δt_J2000)·sin M
      + 0,623°·sin 2M + 0,050°·sin 3M + 0,005°·sin 4M + 0,0005°·sin 5M
      + Σᵢ Aᵢ · cos(0,985 626° · Δt_J2000 / τᵢ + φᵢ)
```

Семь слагаемых возмущений (Aᵢ, τᵢ, φᵢ) — таблица `PERTURBERS`, амплитуды от 0,0018° до 0,0071°. Главный член 10,691° — прямое следствие эксцентриситета орбиты Марса e ≈ 0,0934: в первом порядке амплитуда уравнения центра равна 2e радиан = 10,70°.

### 1.4 Сезон: ареоцентрическая долгота Солнца

```
α_FMS = 270,3871° + 0,524 038 496° · Δt_J2000      (фиктивное среднее Солнце)
L_s   = (α_FMS + (ν − M)) mod 360°
```

**L_s** — положение Марса на орбите, отсчитанное от северного весеннего равноденствия. L_s = 0° — северная весна, 90° — северное лето, 180° — осень, 270° — зима. Это и есть «сезон» в интерфейсе (`seasonLabel`).

### 1.5 Местное время

```
MTC  = (24 · MSD) mod 24                      Coordinated Mars Time, нулевой меридиан
LMST = (MTC − λ_W · 24/360) mod 24            местное среднее солнечное
LTST = (LMST + EOT · 24/360) mod 24           местное истинное солнечное
```

λ_W — западная долгота в градусах (λ_W = 360 − λ_E).

Уравнение времени — разница между истинным и средним Солнцем:

```
EOT = 2,861°·sin 2L_s − 0,071°·sin 4L_s + 0,002°·sin 6L_s − (ν − M)
```

Первые члены — вклад наклона оси (2,861° ≈ связано с наклоном 25,19°), последний — вклад эксцентриситета. На Марсе EOT достигает ±50 минут против ±16 минут на Земле: орбита заметно более вытянута.

**Разница LMST и LTST — физическая, а не косметическая.** LMST — равномерные часы, LTST — то, что показали бы солнечные часы. Полдень по LTST — это момент, когда Солнце реально на меридиане. Поэтому восход и закат считаются по LTST.

### 1.6 Высота и азимут Солнца

Склонение Солнца через L_s:

```
δ = arcsin(0,425 65 · sin L_s) + 0,25° · sin L_s
```

Множитель 0,42565 = sin(25,19°) — синус наклона оси Марса. Второй член — малая поправка алгоритма.

Часовой угол:

```
h = 15° · (LTST − 12)
```

15°/час — Марс поворачивается на 360° за 24 марсианских часа.

Переход в ENU — стандартная сферическая тригонометрия (φ — широта):

```
E = −cos δ · sin h
N =  sin δ · cos φ − cos δ · sin φ · cos h
U =  sin δ · sin φ + cos δ · cos φ · cos h
```

```
высота  = arcsin U
азимут  = atan2(E, N)     от севера по часовой стрелке
```

Вектор (E, N, U) единичный, поэтому **U = sin(высоты)** — это проверяется на данных в разделе 2.4.

### 1.7 Восход и закат

Аналитического решения нет: склонение само зависит от времени. Берётся численно — бисекция по MSD на половине сола от полудня, 40 итераций, критерий «высота Солнца = 0°». 40 делений пополам от полусола дают точность 0,5 сола / 2⁴⁰ ≈ 4·10⁻⁸ с — заведомо избыточно, зато без вывода границ.

Файл: `features/sky/skyMath.ts`, `unixMsForSunCrossing`.

Поиск момента по заданному LTST (`unixMsForLtst`) — итерация простого вида: четыре шага «посчитать LTST, сдвинуть MSD на невязку/24». Сходится быстро, потому что производная LTST по MSD близка к 24 ч/сол.

## 2. Освещённость поверхности

### 2.1 Расстояние до Солнца

```
d = 1,523 679 34 · (1,004 36 − 0,093 09·cos M − 0,004 336·cos 2M
                            − 0,000 31·cos 3M − 0,000 03·cos 4M)   [а.е.]
```

1,52368 а.е. — большая полуось орбиты Марса. Разложение в скобках даёт r/a для эллипса; коэффициент при cos M равен эксцентриситету 0,0934 с точностью до поправок. Расстояние гуляет от 1,381 до 1,666 а.е. — на ±10%.

### 2.2 Поток на верхней границе атмосферы

Закон обратных квадратов:

```
F_TOA = S₀ / d²,    S₀ = 1361 Вт/м² (солнечная постоянная на 1 а.е.)
```

Следствие, которое стоит проговаривать вслух: на Марсе в среднем ≈ 590 Вт/м², в афелии ≈ 490, в перигелии ≈ 715. Разброс по сезону — 46% от минимума. Это не «Марс тусклее Земли в 2,3 раза» одним числом, а функция сезона.

### 2.3 Ослабление пылью: закон Бугера–Ламберта–Бера

Атмосфера Марса почти всегда запылена. Ослабление прямого луча:

```
F = F_TOA · exp(−τ · m),      m = 1 / sin(высота Солнца)
```

- **τ** — оптическая толща по вертикали, безразмерная. Ясный день τ ≈ 0,3–0,5; глобальная пылевая буря τ > 5.
- **m** — воздушная масса: во сколько раз путь луча длиннее вертикального. Плоскопараллельное приближение, у горизонта расходится — при высоте Солнца меньше ~5° формула не применима.

В проекте τ = 0,5 по умолчанию (`DEFAULT_TAU`), управляется из интерфейса прогулки (`walkScene.setTau`).

### 2.4 Проверка на реальных данных

Файл `sites/gale_day.json` — расчёт для кратера Гейл (−5,4°, 137,8° в. д.) на 2026-11-14 12:18:28 UTC. Сверка формул с содержимым файла:

| Величина | По формуле | В файле | Расхождение |
|---|---|---|---|
| sin(высоты) = U | 0,836 439 576 577 | 0,836 439 576 577 | 0 |
| S₀/d² | 526,137 782 | 526,137 782 | 0 |
| Воздушная масса 1/sin h | 1,195 544 | — | — |
| F_TOA·exp(−τm) | 289,394 645 | 289,394 645 | **0** |
| Угловой диаметр | 0,331 336 25° | 0,331 337 44° | 1,2·10⁻⁶ ° |

То есть вся цепочка «расстояние → поток → ослабление» воспроизводится из первых принципов без подгонки. Ночной файл: высота Солнца −74,69°, поток ровно 0.

### 2.5 Угловой диаметр Солнца

```
θ = 2 · arctan(R_☉ / d),   R_☉ = 0,004 650 47 а.е.
```

На Марсе ≈ 0,33° против 0,53° на Земле: диск меньше по площади в 2,6 раза. Это заметно в кадрах — тени резче, полутень уже.

### 2.6 Почему ночной кадр почти чёрный

Физическая причина, а не недостаток рендера: **у Марса нет Луны, способной осветить грунт**. Фобос в полнолуние слабее земной Луны примерно на 8,8 звёздной величины — это в ≈3400 раз меньше освещённости (угловой диаметр втрое меньше лунного, альбедо 0,071 против 0,12). Поэтому при is_night = true `sun_strength_wm2 = 0`, и единственный источник — звёздное небо. Заполнять кадр искусственным светом означало бы врать о наблюдаемости.

## 3. Небо: ориентация Млечного Пути и сумерки

### 3.1 Модель вращения IAU

Чтобы звёзды стояли правильно, нужно знать ориентацию Марса в ICRF на момент наблюдения. Модель IAU/IAG Working Group on Cartographic Coordinates:

```
α₀ = 317,681 43° − 0,1061° · T        прямое восхождение полюса
δ₀ =  52,886 5°  − 0,0609° · T        склонение полюса
W  = 176,630°    + 350,891 982 26° · d    угол нулевого меридиана
```

- **T** — юлианские столетия от J2000 (`d / 36525`), **d** — сутки от J2000.
- Члены с T — **прецессия оси Марса**. Период прецессии ≈ 171 000 лет; за столетие полюс уходит на 0,1°.
- **350,89198226°/сут** — скорость вращения. Отсюда звёздные сутки: 360/350,89198226 × 24 ч = 24,6230 ч = 24 ч 37 мин 22 с. Разница с солнечными сутками (24 ч 39 мин 35 с) — ровно те 2 мин 13 с, на которые Марс должен довернуться, уйдя по орбите.

Матрица перехода ICRF → body-fixed — композиция трёх поворотов:

```
M = R_z(W) · R_x(90° − δ₀) · R_z(90° + α₀)
```

Затем ICRF → ENU добавляет поворот на широту и долготу точки. Матрица ортонормирована, поэтому обратная равна транспонированной (`transpose`) — отдельного обращения не нужно.

Файл: `frontend/src/features/sky/marsSky.ts`.

Контрольные точки для проверок: полюс Галактики (α = 192,8595°, δ = 27,1284°) и центр Галактики (α = 266,405°, δ = −28,936°). По ним видно, что Млечный Путь встаёт над горизонтом так, как должен из этой точки в этот момент.

### 3.2 Сумерки

Сумерки — рассеяние в атмосфере, когда Солнце уже под горизонтом. Пороги:

```
высота > +5°   → день
−18° … +5°     → сумерки
высота < −18°  → ночь
```

−18° — астрономические сумерки (рассеянный свет слабее звёздного фона). Переход не ступенькой, а функцией smoothstep:

```
smoothstep(a, b, x) = t²(3 − 2t),   t = clamp((x − a)/(b − a), 0, 1)
```

У неё нулевая производная на концах, поэтому нет видимого излома при пересечении порога.

```
вес дневного неба = smoothstep(−18°, +5°, высота)
вес видимости звёзд = 1 − smoothstep(−18°, 0°, высота)
```

Звёзды гаснут раньше, чем небо становится дневным (верхний порог 0° вместо +5°) — это соответствует тому, что звёзды пропадают ещё в сумерках.

Файл: `frontend/src/features/sky/skyMath.ts`.

### 3.3 Дальность видимости и пыль

Дальняя дымка привязана к той же оптической толще:

```
дальность_тумана = clamp(L₀ · τ₀ / τ, 1500 м, 8000 м)
```

Обратная пропорциональность τ — прямое следствие закона Бугера: характерная длина ослабления есть 1/коэффициент экстинкции. Для дальнего плана (кратер на горизонте) константа другая, предел 200 км.

Файлы: `features/walk/walkScene.ts`, `features/walk/backdrop.ts`.

## 4. Рельеф и уклоны

### 4.1 Уклон как модуль градиента

Высоты лежат на регулярной сетке. Крутизна в точке — через центральные разности:

```
g_x = (h(x+Δx) − h(x−Δx)) / (2Δx)
g_z = (h(z+Δz) − h(z−Δz)) / (2Δz)
θ   = arctan( √(g_x² + g_z²) )
```

Центральная разность даёт погрешность O(Δ²) против O(Δ) у односторонней — вдвое больший порядок точности при той же стоимости. Если с одной стороны NoData, код честно падает на одностороннюю разность, а если нет и центра — возвращает NaN, а не ноль. Дыра в данных не превращается в «ровное место».

### 4.2 Уклон по направлению движения

Для «что впереди» нужен знаковый уклон вдоль взгляда, а не модуль:

```
θ_вдоль = atan2(h₁ − h₀, L),    L = 10 м
```

База 10 м — компромисс: короче даёт шум отдельных ячеек DTM, длиннее сглаживает реальные уступы. Знак важен: подъём и спуск дают разную скорость и разный метаболизм (раздел 6).

Файл: `frontend/src/features/walk/motion.ts`, классы `TerrainSampler`, функции `slopeFromSamples`, `directionalSlopeDeg`.

### 4.3 Уклон ребра в маршрутизации

```
θ = arctan(Δh / run)
```

где `run` — длина горизонтальной проекции ребра, считается по формуле хаверсина на сфере радиуса 3 389 500 м. Хаверсин вместо теоремы косинусов — устойчивость при малых расстояниях: у косинусной формулы на коротких дугах катастрофическая потеря точности.

### 4.4 Неопределённость — и почему она важна

Из `slopes.py`, статус «измерение»:

- Лучший изученный склон: разные модели рельефа дают **от 11° до 22,5°**. Неопределённость сопоставима с самим порогом 15–20°.
- Экипаж Apollo на глаз оценил склон в **60°**, реально было меньше 30°. Ошибка восприятия вдвое, причина — низкое Солнце и отсутствие привычных ориентиров.
- Район boxwork: средний наклон ровера 8,63°, максимум района 17,53°, максимум миссии 29,12°.

Поэтому уклон показывается с допуском, а не одним числом.

## 5. Скорость ходьбы

```
V = −0,01 · θ + 0,75      [м/с], θ в градусах, область −20° ≤ θ ≤ 20°
```

**Статус: модель.** Линейная аппроксимация, откалиброванная по выходам Apollo. Опорный факт: средняя скорость по 38 эпизодам лунных выходов — **0,728 м/с**, отсюда свободный член 0,75.

Физический смысл коэффициента −0,01: каждый градус подъёма отнимает 1 см/с. На предельных +20° остаётся 0,55 м/с, на спуске −20° получается 0,95 м/с.

Что это **не** значит:
- Это не предел возможностей. Идеальная беговая дорожка даёт 1,74 м/с (`TREADMILL_LIMIT`) — предел, а не рабочая скорость.
- За пределами ±20° модель не определена. Код не экстраполирует молча: `walk_speed` возвращает `status = "outside_model_domain"` и зажимает на границу. В прогулке добавлен мягкий штраф 0,01 м/с на градус сверх 20° и нижняя отсечка 0,1 м/с — чтобы симуляция не вставала колом, но это уже не модель, а ограничитель.

Файлы: `frontend/src/shared/eva/traverse.ts`, `backend/src/martian_map/modules/eva/mobility.py` (источник истины), `frontend/src/features/walk/motion.ts`.

## 6. Метаболизм и кислород

### 6.1 Модель Santee

Метаболическая мощность при ходьбе с грузом:

```
M = 1,5·W + 2(W + L)·(L/W)² + η(W + L)·(1,5·V² + 0,35·V·G)
```

| Символ | Смысл | Единица |
|---|---|---|
| W | масса человека | кг |
| L | масса груза (скафандр, ранец, инструмент) | кг |
| V | скорость | м/с |
| G | уклон | **проценты**, G = 100·tan θ |
| η | коэффициент грунта | безразмерный |

Разбор по слагаемым:

- **1,5·W** — основной обмен, пропорционален массе тела. Не зависит ни от скорости, ни от груза.
- **2(W+L)(L/W)²** — штраф за груз. Квадратичен по относительной нагрузке: нести 45 кг при массе 80 кг стоит не вдвое дороже, чем 22,5 кг, а вчетверо дороже на единицу груза.
- **η(W+L)·1,5V²** — работа против инерции при переносе конечностей. **Квадратична по скорости.**
- **η(W+L)·0,35·V·G** — работа против силы тяжести на подъёме. Линейна и по скорости, и по уклону — это буквально mgh/t.

### 6.2 Поправка спуска

При G ≤ 0 работа против тяжести становится отрицательной, но тело не возвращает её целиком — мышцы работают в тормозном режиме. Эмпирическая поправка:

```
CF = η · [ G(W+L)V/3,5 − (W+L)(G + 6)² / W + (25 − V²) ]
```

Вычитается из M. Минимум по G около −6% — это и есть оптимальный спуск, при котором ходьба дешевле всего. Круче — торможение снова дорожает. Для G > 0 поправка равна нулю.

### 6.3 Коэффициент грунта

```
песок:          η = 1,5 + 1,3 / V²
плотный грунт:  η ∈ [1,0; 1,2]        (вилка, не точка)
```

Для песка η растёт при падении скорости: медленная ходьба по сыпучему грунту означает больше проскальзывания на шаг. При V = 0,75 м/с это η = 1,5 + 1,3/0,5625 = **3,81** — то есть песок почти вчетверо дороже плотного грунта. Грунт на ячейку определяется по тепловой инерции TES.

### 6.4 Марсианская тяжесть: почему коридор, а не число

Здесь честная физическая неопределённость, и проект её не прячет.

Тяжесть на Марсе 0,38 земной. Вопрос: на что умножать 0,38?

```
nasa_tool:       M = 0,38 · (все слагаемые)
inertial_kept:   M = 0,38 · (всё, кроме инерционного) + инерционный член
```

Аргумент за второй вариант физический: **инерция конечностей от тяжести не зависит**. Масса ноги на Марсе та же, разгонять и тормозить её нужно так же. Умножать член 1,5V², отвечающий за инерцию, на 0,38 — значит занижать расход.

Аргумент за первый: так устроен действующий инструмент планирования NASA, и прямые измерения показали метаболизм на марсианской тяжести выше лунного.

Истина между ними, поэтому выдаётся **коридор** [min, max] по двум режимам. Для экипажа 80 кг + 45 кг груза на ровном плотном грунте:

| η | nasa_tool | inertial_kept |
|---|---|---|
| 1,0 | 127,8 Вт | 193,2 Вт |
| 1,2 | 138,3 Вт | 216,7 Вт |

Итоговый коридор 127,8–216,7 Вт. Разброс 70% — и подавать это одним числом было бы подлогом.

Для сверки: проектная средняя мощность выхода 350 Вт, пиковая 530 Вт, фактическая средняя Apollo 273 Вт.

### 6.5 Кислород

```
V̇_O₂ = M / 348,3     [л/мин]
```

Коэффициент 348,3 Вт на литр кислорода в минуту выводится из теплоты сгорания при **дыхательном коэффициенте RQ = 0,85** (смешанное углеводно-жировое питание). Один литр O₂ даёт ≈ 20,9 кДж; 20,9 кДж/мин = 348 Вт. То есть это не подгонка, а калориметрия.

Цена сегмента:

```
t = run / V                           [с]
O₂ = V̇_O₂ · t/60                      [л]
цена метра = O₂(run = 1 м)
```

Берётся середина коридора — именно она служит ценой ребра в поиске маршрута.

В прогулке от первого лица масса тела W и груз L (скафандр с ранцем) берутся из профиля астронавта в настройках, а не из значений по умолчанию; скорость ходьбы (§5) от массы не зависит.

### 6.6 Прыжок

**Статус: модель «та же работа ног».** Считаем, что на Марсе ноги совершают ту же работу, что при прыжке на Земле без скафандра на высоту h_E:

```
W_ног = m · g_E · h_E
h_M   = W_ног / ((m + L) · g_M) = h_E · (g_E / g_M) · m / (m + L)
v     = √(2 · g_M · h_M)          скорость отрыва = скорость приземления
t     = 2 · v / g_M               время полёта
```

Здесь m — масса тела, L — скафандр с ранцем, g_M = 3,720 76 м/с² (≈ 0,38 g_E, §13). Без скафандра (L = 0) прыжок ровно в g_E/g_M ≈ 2,64 раза выше земного. Для 70 кг, скафандра 45 кг и земного прыжка 40 см: h_M ≈ 0,64 м, v ≈ 2,2 м/с, полёт ≈ 1,2 с.

Скорость приземления та же, что на Земле: выше прыжок — не мягче падение, а дольше полёт. Падение в жёстком скафандре с ранцем — главный риск травмы на выходе, поэтому прыгать в скафандре не нужно.

Что модель **не** учитывает: жёсткость скафандра, которая съедает часть работы ног (реальный прыжок будет ниже), и конечное время отталкивания.

В прогулке скорость отрыва берётся из этой модели, а полёт считается по кадрам точным решением для постоянного ускорения g_M, в реальном времени (ускорение времени действует только на горизонтальное движение). Высота глаз камеры пешком ≈ 0,936 × рост (антропометрическая модель) вместо прежних фиксированных 1,7 м.

Файлы: `frontend/src/shared/eva/crew.ts` (`jump`), `tools/crew/README.md`, `frontend/src/features/walk/jump.ts`.

## 7. Правило возврата

**Статус: эксплуатационное правило, не физика.** Принцип — возврат при любом одиночном отказе; двойной отказ не планируется.

```
t_возврата = D / (3,3 км/ч)
O₂_нужно = (422 Вт / 348,3) · (t_возврата + 30 мин)
запас = O₂_осталось − O₂_нужно
```

- **3,3 км/ч = 0,92 м/с** — скорость аварийного возврата, выше модельной 0,75 м/с: при отказе идут быстрее.
- **422 Вт** — аварийная мощность, это 350 Вт проектной средней с надбавкой 20%.
- **30 мин** — неснижаемый резерв.

Точка невозврата — то расстояние, где запас обращается в ноль.

Опорные факты, чтобы не путать: предел Apollo на транспорте 7,6 км, **пеший** радиус 3,1 км. И отдельно: для пеших траверсов ограничивающим ресурсом обычно оказывается **вода на охлаждение, а не кислород** — то есть наша оценка по кислороду оптимистична.

Файлы: `backend/src/martian_map/modules/eva/walkback.py`, `frontend/src/shared/eva/suit.ts`.

## 8. Маршрутизация

### 8.1 A* по сетке высот

Поиск минимальной стоимости на равнопромежуточной сетке. Цена ребра в одном из двух режимов:

```
режим «расстояние»:  w = run · (1 + k·(θ/θ_max)²)
режим «EVA»:         w = run · цена_метра(θ)        [литры O₂]
```

Квадратичный штраф за уклон в первом режиме (k = 3 по умолчанию) — чтобы маршрут предпочитал обход, но не любой ценой.

Эвристика A* должна быть **допустимой** — никогда не переоценивать остаток, иначе найденный путь перестаёт быть оптимальным. Поэтому она берётся как расстояние по прямой, умноженное на минимальную возможную цену метра.

Цена метра табулируется заранее с шагом 0,05° по уклону: в горячем цикле поиска это замена вычисления формулы на индексацию массива. Весь поиск вынесен в Web Worker (`routing.worker.ts`), чтобы не блокировать отрисовку.

### 8.2 Запреты

- Уклон круче `maxSlopeDeg` (по умолчанию 15°) — ребро не существует.
- Изрезанность на 200-метровом масштабе выше порога — ребро не существует. Это про камни и уступы, которых не видно в уклоне усреднённой ячейки.
- Критерий навигации марсохода для сверки: безопасно = уклон < 15° **и** камни не более 7% площади.

### 8.3 Геометрия

Длина ребра — хаверсин на сфере R = 3 389 500 м. Сшивка ног маршрута через научные цели — `waypoints.ts`. Сглаживание трека сплайном Catmull-Rom, ориентация ровера — ортонормальный базис по нормали к сфере (`routeCurve.ts`). Высоты берутся билинейной интерполяцией MOLA (`terrain.ts`).

## 9. Радиация

### 9.1 Фоновая доза

**Статус: измерение.** По данным прибора RAD на Curiosity:

```
типичная доза = 0,64 ± 0,12 мЗв/сол
диапазон по солнечному циклу = 0,25 … 0,95 мЗв/сол
```

Диапазон задаёт солнечный цикл, и подавать одним числом нельзя: в минимуме солнечной активности галактические космические лучи сильнее (гелиосфера хуже их экранирует), в максимуме слабее.

### 9.2 Поглощённая → эквивалентная доза

```
H [мЗв] = D [мкГр] · Q / 1000
```

**Q — коэффициент качества**, учитывает, что тяжёлые ионы повреждают ткань сильнее, чем рентген той же энергии. Варианты из литературы:

| Q | Условие |
|---|---|
| 3,05 ± 0,3 | поверхность, самая цитируемая работа (по умолчанию) |
| 2,1 … 2,7 | уточнение 2019, меньше при более толстой атмосфере |
| 1,2 | разгар солнечного события (протоны мягче) |

### 9.3 Атмосферное экранирование

Атмосфера Марса тонкая, но на пути космических лучей это 16 г/см² — не ноль. Эмпирическая зависимость:

```
D [мкГр/сол] = 220 − K·(p − 840),    K ∈ [0,10; 0,22] мкГр/сол на Па
```

p — давление в Па, 840 Па — опорное. Знак минус: больше давления → толще слой вещества → меньше доза. Применимо только в приповерхностном диапазоне 600–1200 Па.

Поправка на высоту — следствие того же:

```
ΔD ≈ +4 мкГр/сол на каждые 100 м подъёма
```

Измерено на подъёме Curiosity примерно на 150 м (дало +6 мкГр/сол); для |Δh| до 500 м это измерение, дальше — экстраполяция.

### 9.4 Экранирование рельефом

Стена кратера закрывает часть неба, и доза падает:

```
доля = (1 − a)·sky^(n/2) + a,    a ∈ [0,18; 0,24],  n = 2
```

- **sky** — доля видимого неба (1 на открытом месте, меньше в ущелье).
- **a** — доля **альбедной** компоненты: вторичные частицы, рождённые в грунте. Они приходят снизу, поэтому закрытием неба не убираются. Это физический предел экранирования рельефом: даже при sky → 0 остаётся 18–24%.

Проверено на шести точках в кратере Гейл.

### 9.5 Доза за выход

```
H_выход = коридор_дозы × (t_пути [с] / 88 775,244 с) + поправка на перепад высот
```

Делитель — длина сола: доза задана на сол, выход занимает его часть.

Файлы: `backend/src/martian_map/modules/eva/radiation.py`, `shielding.py`, `backend/src/martian_map/api/routes/eva.py`.

## 10. Световая задержка Земля–Марс

```
t_свет = r / c
```

Расстояние r берётся не из формулы, а интерполяцией по таблице эфемерид **JPL Horizons** (`/data/ephemeris/earth_mars_light_time.json`, строится скриптом `backend/scripts/build_light_time.py`). Причина: взаимное положение двух планет на эллиптических орбитах аналитически не выражается без полного решения задачи Кеплера для обеих, а таблица даёт готовый ответ с точностью эфемерид.

Диапазон: от ≈ 3 минут в противостоянии до ≈ 22 минут в соединении. Интерполяция линейная по времени; вне диапазона таблицы возвращается `null`, а не экстраполяция.

## 11. Что в проекте **не** физика

Это важно для защиты не меньше, чем формулы: граница между измеренным, выведенным и назначенным проведена явно.

| Величина | Статус | Почему не физика |
|---|---|---|
| Порог уклона 15° / 20° / 25° | правило | **Численного требования к уклону в стандарте NASA по здоровью экипажа нет** — проверен полный текст. Ссылаться на «требование NASA 20°» нельзя. 20° — действующее правило инструмента планирования, 25° — ориентир сообщества, 15° — консервативная практика |
| 8 ч / 350 Вт бюджет выхода | правило | проектный параметр |
| Резерв 30 мин, возврат 3,3 км/ч, 422 Вт | правило | эксплуатационное соглашение |
| Коридор тяжести | оценка | источники расходятся, см. 6.4 |
| Коэффициент качества Q | оценка | разброс в литературе 1,2–3,05 |

Каждое число в интерфейсе несёт эту пометку рядом с собой.
